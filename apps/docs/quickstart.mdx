In about two minutes you will have Muretto recording your Claude Code sessions and showing what they created.

You need macOS or Linux (Windows through WSL), Claude Code, and an account with at least one [provider](/providers).

<Steps>
  <Step title="Install">
    ```bash
    npm install -g muretto
    ```

    Install globally before you run `muretto init`. The hooks point at the binary's path, so that path has to stay put. `npx muretto` is fine for a quick look, but its cache is temporary.

    <Accordion title="Build from source instead">
      With Go 1.27.3 or newer:

      ```bash
      go install github.com/tolgayayci/muretto/cmd/muretto@latest
      ```

      Homebrew and the `install.sh` script come with the GitHub release.
    </Accordion>
  </Step>
  <Step title="Add the hooks and connect providers">
    ```bash
    muretto init
    ```

    `init` does two things:

    1. It adds Muretto's hooks to your Claude Code settings. It backs the file up to `~/.muretto/backups` first and only appends its own entries.
    2. It asks, provider by provider, whether to connect it. For each one it shows which token to create and which permissions to give it. You paste the token (input is hidden) and Muretto stores it in your OS keychain.

    <Tip>
    Without a terminal, or in CI, set `MURETTO_<PROVIDER>_TOKEN` (for example `MURETTO_SUPABASE_TOKEN`) and run `muretto init --yes`. Tokens from the environment are used but not stored.
    </Tip>
  </Step>
  <Step title="Use Claude Code as usual">
    Ask the agent for real work: a table, a bucket, a deployment. The hooks record each tool call to a local file. They never block or change the agent.
  </Step>
  <Step title="See what was created">
    ```bash
    muretto
    ```

    <Terminal title="muretto" lines={[
      "«b|Muretto» · alice · «d|checked 3 min ago»",
      "",
      "  5 agent-created resources · 5 still exist · «r|3 exposed» · 1 needs review",
      "  3 resources with creator unknown",
      "",
      "  «b|Recent sessions»",
      "  b0b5  today 09:15         bob       prototype orders table                      0 created",
      "  8f2a  Oct 19 14:02        alice     add customer import with file uploads       5 created · «r|3 exposed» · 1 review due",
      "",
      "  → muretto exposed   → muretto session 8f2a   → muretto resources",
    ]} />

    Open one session to see everything it created, and list what is exposed, worst first:

    ```bash
    muretto session 8f2a
    muretto exposed
    ```

    <Terminal title="muretto exposed" lines={[
      "«r|3 exposed» · «d|checked 3 min ago»",
      "",
      "  «r|critical» table      customers        «r|⚠ RLS off: publicly readable»",
      "    Table public.customers is in an API-exposed schema and row level security is off, so anyone with the public key can read it. · session 8f2a (alice)",
      "    → muretto show customers",
    ]} />

    Session and resource arguments accept unique prefixes and names. Every read command takes `--json`.
  </Step>
</Steps>

## If something looks off

```bash
muretto doctor
```

`doctor` checks the hooks, each provider token, the spool of recorded events and the last provider checks. Each failed check comes with a hint.

## Remove Muretto

```bash
muretto uninstall
```

This removes exactly the hooks `muretto init` added, and nothing else. Your local data and tokens stay. To delete them too, run `muretto uninstall --purge`. Then remove the binary with `npm uninstall -g muretto`.
