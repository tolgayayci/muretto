How it works

Set up once.Then just run muretto.

  1. 1

    Install

    $ npx muretto init
    # adds the hook, then connects your providers

    Adds a tiny Claude Code hook that notes what each agent session does. Your settings are backed up, and it's removable.

    ~3.5 ms per callnever blocks the agent
  2. 2

    Connect

    Supabaseread-only token
    Vercelread-only token

    Give it read access to the accounts your agents touch. Tokens live in your OS keychain.

    no account neededno telemetry
  3. 3

    Run

    $ muretto
    Muretto · alice · checked 3 min ago
    5 agent-created resources
    3 exposed · 1 needs review

    See everything your agents created and what's open to the internet right now.

    changes nothing

Under the hood:hooks capture tool calls→read-only APIs list what exists→each resource is exact or creator unknown

Trust and security

It can look.It can't touch.

Read-only, enforced in code

Every provider request goes through one allowlisted module. A test fails if any other code can reach the network.

GET/v1/projects✓ allowed
GET/v1/projects/{ref}/storage/buckets✓ allowed
GET/v1/projects/{ref}/advisors/security✓ allowed
POST/v1/projects✕ refused
DELETE/v1/projects/{ref}✕ refused

Never guesses

78scenarios0wrong labels

In our test suite, mutation-tested. Every resource is exact, with evidence, or creator unknown.

Secrets stay secret

SUPABASE_KEY=eyJhbGciOiJIUzI1NiIs…
SUPABASE_KEY=[REDACTED]

Redacted when recorded and again at output. Tokens live in your OS keychain. Env var values are never stored.

Local-first. No telemetry.

hooks→local SQLite→team sync, opt-in

Works without an account. Team sync is opt-in, and every field it sends is documented.
